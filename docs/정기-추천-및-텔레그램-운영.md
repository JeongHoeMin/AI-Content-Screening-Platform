# 정기 RSS 추천 및 텔레그램 운영

정기 추천은 OpenDART가 아니라 운영자가 설정한 기업 IR RSS 전문만 분석 대상으로 사용한다. 모든 화면 시간과 cron 해석은 한국 표준시(`Asia/Seoul`)이며, 데이터베이스 시간은 UTC로 저장한다.

## 필수 환경 변수

- `DATABASE_URL`: `postgresql+asyncpg://` 형식의 PostgreSQL 연결 주소
- `IR_RSS_FEEDS`: 신뢰할 기업 IR RSS 설정 JSON
- `OPENAI_API_KEY`, `KRX_API_KEY`: 기존 분석 실행에 필요한 키
- `SCHEDULE_SETTINGS_PASSWORD`: 32자 이상 임의 값. `/settings` 접근 비밀번호이며 서버가 HttpOnly session cookie로만 변환한다.
- `SCHEDULE_COOKIE_SECURE`: 기본 `true`. HTTPS 운영에서 유지한다. 로컬 HTTP 검증에서만 명시적으로 `false`를 설정한다.

텔레그램 전송을 켠 경우에만 아래 두 값을 함께 설정한다. 한 값만 설정하면 worker는 안전하게 시작을 거부한다.

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

토큰·채팅 ID·RSS 원문·프롬프트·외부 API 응답 전문은 로그 또는 JSONL audit에 남기지 않는다.

## 실행 방법

1. migration을 적용한다.

   ```bash
   docker compose exec -T dashboard /app/.venv/bin/alembic upgrade head
   ```

2. dashboard와 `schedule-worker`를 시작한다.

   ```bash
   docker compose --env-file /secure/screening.env up --build -d
   ```

3. `/settings`에서 `SCHEDULE_SETTINGS_PASSWORD`를 입력한다. 성공한 브라우저에만 HttpOnly session cookie가 발급되고 schedule API가 열린다. HTTPS reverse proxy 운영에서는 `SCHEDULE_COOKIE_SECURE=true`를 유지한다. cron은 `0 8 * * *`처럼 5개 필드를 쓴다.

`schedule-worker`는 30초마다 DB의 due slot을 확인한다. PostgreSQL lease와 `(job_id, scheduled_for)` 고유 제약으로 같은 실행 슬롯을 중복 처리하지 않는다. 실행 완료 후에만 텔레그램 요약을 best-effort로 보낸다. 전송 실패는 분석 결과를 실패 처리하지 않는다.

## 운영 확인

```bash
docker compose logs --tail=100 schedule-worker
docker compose exec -T postgres psql -U screening -d screening -c \
  'SELECT job_id, scheduled_for, status, error_type FROM scheduled_recommendation_executions ORDER BY started_at DESC LIMIT 20;'
```

`scheduled_recommendation_jobs`에는 설정과 다음 실행 시각, `scheduled_recommendation_executions`에는 실행 상태만 저장한다. 추천 당시 매수 가격 및 수익률 통계는 다음 별도 변경 단위에서 저장·표시한다.
