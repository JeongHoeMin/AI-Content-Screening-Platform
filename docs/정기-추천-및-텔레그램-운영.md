# 정기 RSS 추천 및 텔레그램 운영

정기 추천은 OpenDART가 아니라 운영자가 설정한 기업 IR RSS 전문만 분석 대상으로 사용한다. 모든 화면 시간과 cron 해석은 한국 표준시(`Asia/Seoul`)이며, 데이터베이스 시간은 UTC로 저장한다.

## 필수 환경 변수

- `DATABASE_URL`: `postgresql+asyncpg://` 형식의 PostgreSQL 연결 주소
- `IR_RSS_FEEDS`: 신뢰할 기업 IR RSS 설정 JSON
- `OPENAI_API_KEY`, `KRX_API_KEY`: 기존 분석 실행에 필요한 키
- `SCHEDULE_SETTINGS_PASSWORD`: 32자 이상 임의 값. `/settings` 접근 비밀번호이며 서버가 HttpOnly session cookie로만 변환한다.
- `SCHEDULE_COOKIE_SECURE`: 기본 `true`. HTTPS 운영에서 유지한다. 로컬 HTTP 검증에서만 명시적으로 `false`를 설정한다.

텔레그램 전송을 켠 경우에만 아래 두 값을 함께 설정한다. 한 값만 설정하면 worker는 안전하게 시작을 거부한다.

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

토큰·채팅 ID·RSS 원문·프롬프트·외부 API 응답 전문은 로그 또는 JSONL audit에 남기지 않는다.

## 추천 가격 설정과 한계

KIS 실시간 가격은 선택 사항이다. 보안 환경 파일에 아래 **이름만** 추가하고 값은 저장소·문서 예시·로그에
기록하지 않는다.

- `KIS_APP_KEY`, `KIS_APP_SECRET`: 함께 설정해야 하는 KIS 자격 증명
- `KIS_ACCOUNT_PRODUCT_CODE`: 기본값 `01`
- `KIS_BASE_URL`: 기본값 `https://openapi.koreainvestment.com:9443`
- `KIS_TIMEOUT_SECONDS`: 기본값 `10`

KIS가 설정되지 않았거나 현재가를 확인할 수 없으면 시스템은 `KRX_API_KEY`를 사용하는 KRX의 최근 거래일
종가를 최대 7일 범위에서 찾는다. 두 제공자 모두 가격을 반환하지 못하면 `가격 미확인`으로 남기며 0원,
추정 가격, 수익률을 만들지 않는다. 가격 관측 실패는 다른 추천이나 정기 실행을 실패시키지 않는다.

추천·성과 화면과 Telegram의 시간은 KST(`Asia/Seoul`)로 표시하고 DB 시각은 UTC로 저장한다. BUY의
`그날 샀더라면`, SELL의 `그날 팔았더라면` 표시는 entry와 latest 가격만 비교한 사후 단순 가격 비교다.
수수료·세금·배당, 실제 체결 가격·체결 시각, 슬리피지, 보유 비용은 반영하지 않으므로 투자 조언이나 실현
수익률이 아니다.

## 실행 방법

1. dashboard와 `schedule-worker`를 시작한다. Compose의 `db-migrate`가 PostgreSQL healthcheck 뒤 migration을
   적용한 후 두 서비스를 시작한다.

   ```bash
   docker compose --env-file /secure/screening.env up --build -d
   ```

2. KIS 설정을 추가·변경했거나 worker를 재기동해야 하면 같은 보안 환경 파일로 두 runtime service를 재생성한다.

   ```bash
   docker compose --env-file /secure/screening.env up --build -d --force-recreate dashboard schedule-worker
   ```

3. `/settings`에서 `SCHEDULE_SETTINGS_PASSWORD`를 입력한다. 성공한 브라우저에만 HttpOnly session cookie가 발급되고 schedule API가 열린다. HTTPS reverse proxy 운영에서는 `SCHEDULE_COOKIE_SECURE=true`를 유지한다. cron은 `0 8 * * *`처럼 5개 필드를 쓴다.

`schedule-worker`는 30초마다 DB의 due slot을 확인한다. PostgreSQL lease와 `(job_id, scheduled_for)` 고유 제약으로 같은 실행 슬롯을 중복 처리하지 않는다. 실행 완료 후에만 텔레그램 요약을 best-effort로 보낸다. 전송 실패는 분석 결과를 실패 처리하지 않는다.

## 운영 확인

```bash
docker compose logs --tail=100 schedule-worker
docker compose exec -T postgres psql -U screening -d screening -c \
  'SELECT job_id, scheduled_for, status, error_type FROM scheduled_recommendation_executions ORDER BY started_at DESC LIMIT 20;'
```

`scheduled_recommendation_jobs`에는 설정과 다음 실행 시각, `scheduled_recommendation_executions`에는 실행 상태만 저장한다. 가격 snapshot은 별도 recommendation price storage에 entry/latest identity로 저장하며, 원래 entry를 변경하지 않는다. credential, access token, authorization header, raw provider payload는 어떤 저장소·로그·SSE·Telegram에도 저장하지 않는다.
